### 첨부는 파일을 복사해 옮겼다 (`ri:page` 참조 금지)

`<ri:attachment ri:filename="…">` 는 **같은 페이지의 첨부**만 가리킨다. 섹션만 복사하면 8개 참조가 전부 깨지므로, 원본 페이지에서 8개 파일을 **내려받아 새 페이지에 같은 파일명으로 업로드**했다(HTTP 200 · 8/8). `<ri:page>`로 다른 페이지 첨부를 가리키는 방식은 **금지**(2026-07-30 규칙 — space-key/제목이 한 글자만 어긋나도 「알 수 없는 첨부파일」로 깨진다).

### 위상만 조정했다 — 내용은 verbatim

| 항목 | 원본(캠페인 문서) | 신규 페이지 |
|---|---|---|
| 위상 | `<h4>OA</h4>` — **LV 하위** | **`<h3>OA MSG</h3>`** — UIT·LV와 동급 |

**이유**: OA는 FE 팀이 아니라 LINE OA 콘솔·Messaging API 발송이므로 LV 하위에 두면 **팀 프리픽스·`{0}` 치환자 규칙이 잘못 상속**된다(2026-08-05 확정 결정). 캠페인 문서는 이 결정 이전 구조다. **`<h4>OA</h4>` → `<h3>OA MSG</h3>` 태그 1개만 바꾸고 나머지는 문자 그대로 유지**했다.

### ⚠️ `{{amount}}`를 그대로 두었다 — 편집 시 `{{total_amount}}`로 교체 필요

이관된 OA 영역에는 `{{amount}}`가 **11곳** 있다(안내문 + 번역표). 오늘 확정된 표준은 **`{{total_amount}}`**(용어집 v4.1 `oa_variables`, `md/OA.md` §2-1)이지만 **의도적으로 치환하지 않았다**:

- 같이 이관한 **Flex zip 4종 안의 JSON도 `{{amount}}`** 를 쓴다. 본문만 바꾸면 **본문과 첨부가 어긋난다.**
- `md/OA.md` §2-1은 **기존 산출물 소급 치환을 금지**한다. 이관본은 사용자가 편집할 출발점이므로 원본 상태를 유지하는 것이 안전하다.

## 2. ⛔ 첨부 파일명이 깨졌다가 복구했다

첨부 갱신에 `-F "file=@/tmp/.../newzip_flex_….zip"` 를 쓰자 curl이 **basename을 그대로 파일명으로 보내** 첨부 제목이 `newzip_flex_….zip`로 바뀌었다. 본문은 `flex_….zip`을 참조하므로 **링크 3개가 깨진 상태(v2)** 가 됐다.
