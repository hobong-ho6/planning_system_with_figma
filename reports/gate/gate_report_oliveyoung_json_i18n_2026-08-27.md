## 0. 번역 소스 결정 — 기존 XLT 재사용이 원칙

kr 4파일의 번역 대상 **44개 문자열 중 43개가 기존 XLT 키와 동일한 문구**였다. 임의 재번역하면 같은 문구가 화면과 json에서 달라지므로, **XLT 정본의 5개 언어 값을 그대로 가져왔다**(`md/translate.md` 「같은 문구 = 같은 키 재사용」의 데이터 파일 적용).

| 파일 | 문자열 | XLT 재사용 | 신규 번역 |
|---|---:|---:|---:|
| `checkout-kr.json` | 6 | 6 | 0 |
| `guide-kr.json` | 9 | 9 | 0 |
| `info-kr.json` | 17 | 17 | 0 |
| `summary-kr.json` | 12 | 12 | 0 |
| `review-jp.json` | 24 | 0 | **12**(body) · 12(display_name = 원문 유지) |
| **합계** | **68** | **44** | **12** |

- `notice.descriptions[0~1]`·`caution.descriptions[0~5]`는 json에서 **배열로 쪼개져** 있으나 XLT에서는 `UF_voucher_detail_guide_value`·`UF_voucher_detail_caution_value`에 **여러 줄 한 덩어리**로 들어 있다. 줄 단위로 분해해 `-` 접두를 떼고 매칭했다.
- **매핑 누락 0건**(4파일 44경로 전부 매핑 · 역방향 미사용 매핑도 0건).

### 데이터 파일에 맞춘 2가지 변환 (XLT → json)

| 변환 | 이유 |
|---|---|
| **치환자 `{{0}}` → 실제 값 `5`** | XLT는 캐시백률을 `{{0}}`로 변수화했으나(2026-08-26 사용자 확정) **json은 렌더 데이터**라 치환자가 남으면 화면에 `{{0}}%`가 그대로 보인다. 이 상품(올리브영 5만원권)의 실제 요율 **5%**를 넣었다 — json 원문도 `5%`였다. 해당 2건: `checkout steps[3]` · `guide steps[2].description` |
| **개행 평탄화** | XLT 값에는 화면 줄바꿈용 `\n`이 있으나 json 원문에 개행이 없으면 제거했다(원문 구조 보존). `info usage.description`처럼 **json 원문에 개행이 있으면 유지**한다 |
