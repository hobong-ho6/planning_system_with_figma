### (d-2) 추가 개선·제안 안내

1. **`{0}(JST)` 표기 위치 확인** — 치환자 값에 이미 시간대가 포함돼 오는 경우 `(JST)`가 중복 노출된다. FE 전달 값 형식(예: `2026-07-31 23:59`)을 확인해 주세요. 값에 시간대가 포함되면 `(JST)`를 문구에서 제거해야 합니다.
2. **`terms_wallet_fixed` 정책 의미 확인** — 구 문구는 지급 조건을 *일본 LINE 계정 기반 지갑*으로, 신 문구는 *일본에서 Unifi에 가입한 사용자*로 규정합니다. 대상 판정 기준이 LINE 계정 국가 → 가입 국가로 바뀐 것이라면 FE/BE 판정 로직과의 정합 확인이 필요합니다.
3. **`terms_jp_excluded`의 `먼저`** — "먼저 당첨되어도"는 선착순 뉘앙스를 담고 있어 4개 언어 모두 `first/先に/先/ก่อน`로 직역했습니다. 의도가 단순히 "당첨되어도"라면 `먼저`를 삭제하는 편이 명확합니다(삭제 시 4개 언어 재패치 필요).
4. **Screen 표 검토 표시(노란 하이라이트)** — 3키 셀의 노란 배경은 처리 완료 관행에 따라 제거했습니다(이전 세션 선례). 파란색 강조 텍스트는 기획자 표기이므로 그대로 두었습니다.
5. **엑셀 파일명 날짜** — 첨부 파일명이 `xlt_output_LV_20260727.xlsx`로 고정돼 실제 갱신일(2026-07-29)과 다릅니다. 본문 링크 유지를 위해 파일명은 그대로 두고 첨부 버전만 올렸습니다(v14 → v15). 파일명에 날짜를 반영할지 결정 필요.

### 3번 재번역 게이트 (자동 + 수동)

- **자동 검증 재실행**: 전체 74키 **P0 = 0** / P1 103 / P2 27. 대상 키 `terms_jp_excluded`의 이슈 **0건**(P0·P1·P2 모두 없음).
- **수동 검토(변경 4셀 전수)**: en 초안 `have already won`은 `win`의 불규칙 활용이라 검증기 어미 허용 규칙에 걸려 **새 P1을 유발** → 의도를 유지하면서 `even if they win a Lucky Ball`로 정리해 해소. ja·zh·th는 각각 `当選`·`中獎`·`ถูกรางวัล` 등재값 보존 확인.

### 4번 용어집 처리 — `당첨` 보류 사유 (정정)

앞서 (d-1)에서 제안한 "en·th 명사형 **병기**"는 **구현 불가**임을 확인했다(정정):

- 용어집 스키마는 **언어당 단일 값**이고, `validate_translation._term_in_text`는 **en 외 언어에서 완전 부분문자열 일치**를 요구한다 → `win / winning` 같은 슬래시 병기는 모든 행에서 불일치가 되어 오탐이 오히려 늘어난다.
- 일관성 검증(landpress §4 기준 3, LV+UIT 76행 전수): `당첨` 포함 **12행** 중 en `win` 일치 3행 / th `ถูกรางวัล` 일치 3행. 나머지는 `당첨금` 계열(`prize`·`เงินรางวัล`)로, 등재값을 명사형으로 바꾸면 반대 방향 오탐이 발생한다 → **추가·수정 보류**가 규정에 맞는 처리.
- **근본 해결 제안(별건)**: 검증기에 **최장일치 우선** 규칙 도입 — ko 텍스트에서 `당첨금`이 매칭되면 그 구간에 대해 `당첨` 검사를 생략. 이 개선이 들어가면 `당첨` 관련 P1 오탐 대부분이 자동 소멸한다. 코드 변경이므로 별도 승인 후 진행 권장.
