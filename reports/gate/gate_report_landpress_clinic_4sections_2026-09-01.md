## (d) 추가 개선·제안 (권장 — 임의 적용하지 않음, 사용자 결정 사안)

### (d-1) 용어집 보완 권장
**없음.** P1 18건이 전부 「기존 등재값과 일관한 동사형 사용 vs 용어집의 명사형 표기」 충돌이다. 용어집을 넓히는 대신 **검증기 쪽 문맥 예외**가 맞는 사안이라 용어집 버전 상승을 권장하지 않는다. 권장 표기 실측(`fetch_xlt_registry.py`)도 수행하지 않았다 — 신규 표기 제안이 없기 때문.
- 단, 검증기 개선 후보 1건: **P2 마침표 스타일 검사에 `?`·`？`·`!`·`！` 종결을 정상으로 인정** — 질문형 문구가 늘어나면 반복 오탐이 난다.

### (d-2) 추가 개선·제안
1. **FAQ 답변 3건은 Claude 작성 샘플이다 (검토 필요)** — Figma에는 **질문 4개 중 답변이 1개만(faq_1)** 노출되어 있다. `faq_2`·`faq_3`·`faq_4` 답변은 위키 Policy 표·`change_cancel`·`process` 정책을 근거로 작성한 **샘플**이므로, 확정 문구는 기획 검토가 필요하다.
   - faq_2 A ← `change_cancel` #2 (방문 후 변경·미시술 가능)
   - faq_3 A ← `process` step4 (결제 확인 후 15% 포인트)
   - faq_4 A ← `process` step3 (사전 결제 없이 시술 후 결제)
2. **캐시백률 리터럴 `15%`** — Figma 문구대로 반영. 사용자가 **FE에 API 조달 가능 여부를 문의 예정**. 클리닉별로 다른 값이면 이 문장들만 치환자 처리로 전환해야 한다(영향 범위: `process` step4 title·description, `faq_3` 답변 — 5개 언어 × 3문구).
3. **`cautions` 5줄 vs 디테일 화면 3줄 불일치** — 브릿지 프레임은 5줄, 디테일 프레임은 3줄만 노출된다. JSON은 **5줄 상위집합**을 담았다. 화면별로 일부만 노출할지, 양쪽 5줄로 통일할지 결정이 필요하다.
4. **`process`는 필드명 미지정** — 사용자가 확정한 3개(`cautions`·`change_cancel`·`faq`)에 없어 관례상 `process`로 생성했다. 다른 이름(`treatment_process` 등)을 쓸 예정이면 알려주면 재생성한다.
5. **Figma 원본 수정 요청 대상**(위 (1a) alias) — `change_cancel` #1 문체·#2 마침표. XLT 등재값(`UF_clinic_detail_cancel_1`·`_2`) 한국어도 함께 갱신해야 화면·시스템·Landpress가 일치한다. 별도 2키 패치 엑셀이 필요하면 생성한다.
6. **`faq_1` 답변의 `\n`** — Figma의 U+2028을 표준 `\n`으로 보존했다. FE가 개행을 렌더하지 않는다면 두 문단을 별도 필드로 분리하거나 공백 1개로 합치는 처리가 필요하다.
