# 엑셀 다국어 번역 검증 체크리스트

> Unifi 프로젝트 다국어 리소스 파일을 검증·교정·번역할 때 사용하는 표준 프로세스입니다.

## 개요

검증은 항상 **3단계 순서**로 진행합니다. 한국어 원문이 다른 언어로 번역되는 작업 흐름이므로, 원문을 먼저 정리해야 다국어 일관성이 보장됩니다.

```
1단계: 한국어 맞춤법·띄어쓰기 검토 (원문 정리)
        ↓
2단계: 용어집 위반 확인 (표준 표기 점검)
        ↓
3단계: 다른 언어 번역 검토 (의미·자연스러움 확인)
        ↓
[작업 1] 발견 사항 정리 및 우선순위 분류
[작업 2] 엑셀 파일 업데이트 (선택)
[작업 3] 신규 번역 추가 (해당 시)
```

### 파일 구조 파악 (필수 선행 작업)

검증 시작 전 다음을 확인합니다:

| 확인 항목 | 방법 |
|---|---|
| 시트 이름 | 보통 `properties` |
| key 열 이름 | `Key ID` 또는 첫 번째 열 (Unnamed: 0) |
| 전체 행 수 | `len(df)` |
| 언어 열 구성 | 5개 채움 (en/ko/ja/zh_TW/th) vs 19개 전체 |
| 각 언어 채움 비율 | `df[col].notna().sum() / len(df)` |

```python
import pandas as pd
df = pd.read_excel(path, sheet_name='properties')
for col in df.columns:
    print(f"{col}: {df[col].notna().sum()}/{len(df)}")
```

## 1단계: 한국어 맞춤법·띄어쓰기

### 자동 검출 (스크립트로 가능)

| 패턴 | 검사 항목 | 예시 |
|---|---|---|
| 오타 | `미선` → `미션` | 행에 `미선`이 있으면 의심 |
| 맞춤법 | `되요` → `돼요` | `지급되요` → `지급돼요` |
| 맞춤법 | `됬-` → `됐-` | `소진됬` → `소진됐` |
| 띄어쓰기 (의존명사) | `유지시` → `유지 시`, `할수있-` → `할 수 있-` | "시", "수", "것" 등 |
| 비표준 공백 | `\xa0` (non-breaking space) 포함 | 셀 끝에 자주 발견 |
| 공백 | 이중 공백, 앞/뒤 공백 | `re.search(r'\s{2,}', text)` |
| `/n` 오타 | 백슬래시 대신 슬래시 | `/n` → `\n` |

### 수동 검토 (사람이 직접 봐야 함)

자동 도구로 잡히지 않는 항목들:

| 패턴 | 검사 항목 | 발견 예시 |
|---|---|---|
| **표현 어색** | "미션하고" → "미션 완료하고" | "다양한 보너스 미션하고 리워드..." |
| **조사 누락** | "미션 참여하고" → "미션을 완료하고" | "다양한 미션 참여하고..." |
| **표현 중복** | 한 문장 내 동일 어구 반복 | "자세한 자산 정보는...자세한 자산 정보는..." |
| **의미 모호** | "실물 결제" vs "매장 결제" | EN의 in-store 의미와 매칭 |
| **종결 어미 일관성** | 해요체 vs 합쇼체 혼용 | "유지해주세요" vs "유지해야 합니다" |
| **마침표 일관성** | 셀별 마침표 사용 정책 | -습니다=○, -어요=✕ 혼재 |

### 검토 시 비교 기준

같은 파일 내 **유사 컨텍스트의 다른 셀**을 비교 기준으로 사용:
- 행 26 `미션을 완료하고` vs 행 2 `미션 참여하고` → 행 2를 행 26과 통일
- 행 11 `필수 미션` vs 행 35 `필수미션` → 띄어쓰기 통일

### ✏️ 정책 결정 사항 (수정 전 확정 필요)

- 종결 어미 톤: 약관/안내는 합쇼체, 사용자 메시지는 해요체로 통일
- 마침표 정책: 모든 평서문에 마침표 ○ vs 해요체는 마침표 ✕
- "출석체크" 등 합성어 띄어쓰기 정책

## 2단계: 용어집 위반

### A. 한국어 용어집 키워드 매칭

한국어 셀에 용어집의 한국어 키워드가 들어 있을 때 다른 언어 셀에 지정 번역어가 포함되어 있는지 확인.

```python
# 긴 용어 우선 매칭 (예: "거래 내역"이 "거래"보다 우선)
terms_sorted = sorted(glossary['terminology'].items(), key=lambda x: -len(x[0]))
```

**중요**: 용어집 매칭 위반의 대부분은 **정상 의역**입니다. 진짜 오류와 구분해야 합니다.

| 위반 패턴 | 판정 | 사유 |
|---|---|---|
| 송금 → EN `transfer/transferring` | ✅ 정상 의역 | 금융 도메인 표준 |
| 송금 → TH `โอนเงิน` | ✅ 정상 의역 | 태국어 금융 표준 |
| 확인 → EN `OK/Confirm` (버튼 라벨) | ✅ 정상 의역 | UI UX 표준 |
| 변경 → ZH `變更/變動` | ✅ 정상 의역 | 동의어 |
| 자산 → EN `funds` (컨텍스트) | ✅ 정상 의역 | 컨텍스트 의역 |

### B. 예외 패턴 표기 통일 (USDT, JPYC, PIN, API, URL, Apple, Google, IDRP)

대소문자가 정확히 일치해야 함:

| 예시 | 위반 | 수정 |
|---|---|---|
| `USDt` | 🔴 | `USDT` |
| `usdt` | 🔴 | `USDT` |
| `idrp.io` (도메인) | ✅ 정상 (도메인은 소문자) | 그대로 유지 |

**단어 경계 검사**: 도메인(`jpyc.co.jp`), 식별자(`api_key`) 내 부분 문자열은 제외해야 함.

### C. zh_TW 한자 변형

| 한자 쌍 | 표준 | 이형 |
|---|---|---|
| 자산의 産 | `產` (U+7522, 표준 번체) | `産` (U+7523, 일본식/이형) |
| 대만의 臺 | `臺` (정자) | `台` (속자) |

같은 파일 내에서 어느 한 행만 다른 형태를 쓰면 통일 필요.

### D. th_TH 자산 표기 일관성

용어집 표준 `สินทรัพย์`(자산) vs 동의어 `ทรัพย์สิน`(재산, 어순 다름) 혼용 검사.

### E. 도메인 핵심 용어 (용어집에 없는 자주 쓰이는 용어)

각 프로젝트의 도메인 용어를 추가로 검사:

| 한국어 | en_US | ja_JP | zh_TW | th_TH |
|---|---|---|---|---|
| 럭키볼 | Lucky Ball | ラッキーボール | 幸運球 | ลูกบอลนำโชค |
| 미션 | mission | ミッション | 任務 | ภารกิจ |
| 보상/리워드 | reward | リワード / 報酬 / 特典 | 獎勵 | รางวัล |
| 이벤트 | event | イベント | 活動 | กิจกรรม |

## 3단계: 다른 언어 번역 검토

### A. 빈칸 / 언어 혼입 / placeholder / `/n` 오타

이 4가지는 자동 검증 도구로 100% 검출 가능:

| 검증 | 도구 | 예시 |
|---|---|---|
| 빈칸 | `pd.isna(v)` | 5개 채워야 할 언어 중 1개 누락 |
| 언어 혼입 | 유니코드 범위 | en_US 셀에 한글 포함 (컬럼 swap) |
| placeholder | 정규식 매칭 | KO `{0}{1}` vs ZH `{0}{{1}}` |
| `/n` 오타 | 정규식 | `여기서/n부터` (백슬래시 대신 슬래시) |

### B. 컬럼 swap 탐지 (중요!)

데이터 입력 단계에서 자주 발생하는 오류. en_US 셀에 한글이, ko_KR 셀에 영어가 들어있는 경우:

```python
# en_US 열에 한글 + ko_KR 열에 영어만 있으면 swap 의심
if re.search(r'[\uac00-\ud7a3]', en) and not re.search(r'[\uac00-\ud7a3]', ko):
    print("⚠️ 컬럼 swap 의심")
```

### C. ja_JP 한국어 직역 패턴

한국어를 그대로 한자로 옮겼지만 일본어로는 어색한 표현:

| KO | JA 직역 (어색) | JA 자연스러운 표현 |
|---|---|---|
| 출석 | 出席 | チェックイン |
| 출석체크 | 出席チェック | チェックイン |
| 친구 추가 | 友だち追加 | 友だち追加 (이건 정상) |

### D. 한 문장 안 단어 중복 (다국어 동시 발생 가능)

한국어에서 어색한 중복이 다른 언어에도 그대로 전달되는 경우:

```
KO: 자세한 자산 정보는 표시되지 않을 수 있으며 자세한 자산 정보는 여기서 확인해 주세요.
EN: Detailed asset information may not be shown. Please check your detailed asset information here.
JA: 詳細な資産情報は表示されない場合があります。詳細な資産情報はこちらでご確認ください。
```

→ **한국어 원문부터 정리** 후 다른 언어 동시 수정.

### E. 마침표 일관성

| 언어 | 일반 관습 |
|---|---|
| en_US | 평서문 끝 `.`, 의문문 `?` 표준 |
| ko_KR | 해요체는 마침표 ✕, 합쇼체는 ○ (의도된 카피는 ✕도 허용) |
| ja_JP | 평서문 끝 `。` 표준 |
| zh_TW | 평서문 끝 `。` 표준 |
| **th_TH** | **태국어는 일반적으로 마침표 사용 안 함** (관습) |

→ KO와 TH 사이의 마침표 불일치는 정상.

### F. 도메인 표현 의역 검토

각 언어의 자연스러운 표현 패턴:

| 의역 카테고리 | 예시 |
|---|---|
| 금융 용어 | 송금 → EN `transfer`, TH `โอนเงิน` (X `send/ส่ง`) |
| 버튼 라벨 | 확인 → EN `OK`, TH `ตกลง` (X `check/ตรวจสอบ`) |
| 마케팅 표현 | 공식 채널 vs 공식 계정 (LINE 한국 마케팅 표준) |
| 의역 가능성 | bonus → ZH `額外` 권장 (X `獎勵`는 리워드 의미와 중복) |

## 작업 단계

### [작업 1] 발견 사항 분류 및 우선순위

심각도 분류 기준:

| 심각도 | 카테고리 | 처리 |
|---|---|---|
| 🔴 P0 (Critical) | 빈칸, 컬럼 swap, 명백한 오타, 언어 혼입, /n 오타, 용어집 표기 위반 | 즉시 수정 |
| 🟡 P1 (Medium) | 표현 어색, placeholder 불일치, 일관성 위반 (용어집 매칭) | 검토 후 일괄 수정 |
| 🟢 P2 (Low) | UI 라벨 의심, 스타일 선호 (쉼표/마침표) | 정책 결정 후 적용 |

key_id 기준 그룹화 시 한 키에 여러 이슈가 있을 수 있으므로 가장 높은 심각도로 분류.

### [작업 2] 엑셀 파일 업데이트

**원칙**:
1. 원본 파일 복사본에 작업 (원본 보존)
2. `openpyxl`로 셀 단위 값만 변경 (서식·다른 셀 데이터 유지)
3. 변경 전 모든 `before` 값을 expected와 정확히 매칭 검증
4. 한 셀이라도 매칭 실패 시 해당 셀만 스킵, 나머지는 진행

```python
from openpyxl import load_workbook
import shutil

src = 'original.xlsx'
dst = 'original_corrected.xlsx'
shutil.copy(src, dst)
wb = load_workbook(dst)
ws = wb['properties']

# 헤더로 컬럼 인덱스 추출
header = {ws.cell(row=1, column=c).value: c for c in range(1, ws.max_column + 1)}

for c in corrections:
    cell = ws.cell(row=c['row'], column=header[c['lang']])
    if cell.value != c['before']:
        print(f"❌ 스킵: {c['row']} {c['lang']}")
        continue
    cell.value = c['after']

wb.save(dst)
```

### [작업 3] 신규 번역 추가 (해당 시)

한국어만 채워져 있고 다른 언어가 비어있는 경우:

1. **한국어 원문 먼저 교정** (1-3단계 검증 완료)
2. **용어집 + 이전 파일의 표기 정책 일관성 유지**
3. **빈 셀에만 추가** (기존 값 덮어쓰지 않음)
4. **미사용 언어 열은 그대로 빈 상태 유지**

번역 시 표기 정책 참조 표:

| 용어 | en_US | ja_JP | zh_TW | th_TH |
|---|---|---|---|---|
| 자산 | funds (컨텍스트) / asset | 資産 | 資產 (U+7522) | สินทรัพย์ |
| 송금 | transfer / transferring | 送金 | 轉帳 | โอนเงิน |
| 출석/체크인 | check in | チェックイン (X 出席) | 簽到 | เช็คอิน |
| 미션 | mission(s) | ミッション | 任務 | ภารกิจ |
| 리워드 | reward(s) | リワード | 獎勵 | รางวัล |
| 럭키볼 | Lucky Ball | ラッキーボール | 幸運球 | ลูกบอลนำโชค |
| bonus (추가) | bonus | ボーナス | 額外 (X 獎勵) | โบนัส |
| Unifi / USDT / JPYC | 모든 언어에서 그대로 유지 |

## 산출물 표준 형식

각 검증 결과는 다음 3종 파일로 정리:

| 파일 | 용도 |
|---|---|


### 한국어 오타·어색

| 패턴 | 빈도 | 수정 |
|---|---|---|
| `미선` (미션 오타) | 자주 | `미션` |
| `미션하고` | 자주 | `미션 완료하고` |
| `미션 참여하고` | 자주 | `미션을 완료하고` |
| `지급되요` | 가끔 | `지급돼요` |
| `유지시` | 가끔 | `유지 시` |
| `정보가변경된` | 가끔 | `정보가 변경된` |
| `캠페인 입니다` | 가끔 | `캠페인입니다` |
| `필수미션` vs `필수 미션` 혼용 | 가끔 | `필수 미션` |

| `실물 결제` | 가끔 | `매장 결제` (in-store) |

| 끝에 `\xa0` 잔존 | 가끔 | 일반 공백으로 |

### 컬럼/구조 문제

| 패턴 | 빈도 | 수정 |
|---|---|---|
| en_US ↔ ko_KR 컬럼 swap | 가끔 | 두 셀 값 swap |
| key_id 앞에 공백 (특히 `\xa0`) | 가끔 | strip + `\xa0` 제거 |
| key_id 중복 (값 동일) | 자주 | 한 행 삭제 |
| key_id 중복 (값 다름) | 가끔 | key 분리 또는 한쪽 선택 |

### ja_JP 부자연

| 패턴 | 수정 |
|---|---|
| `出席` / `出席チェック` | `チェックイン` |
| 한국어 조사 잔존 (예: `友だ치`) | `友だち` |
| `JPYC를` | `JPYCを` |

### zh_TW 표기

| 패턴 | 수정 |
|---|---|
| `資産` (U+7523) | `資產` (U+7522 표준 번체) |
| `USDt` 등 대소문자 | `USDT` 통일 |
| 한 문장 내 `獎勵` 중복 | 앞쪽을 `額外`로 |
| `/n` (백슬래시 누락) | `\n` |

## 검증 도구 사용법

### 기본 실행

```bash
python validate_translation.py {엑셀_파일} \
  --key-column "Key ID" \
  --glossary glossary.json \
  --output report.md \
  --json result.json
```

### 옵션

| 옵션 | 설명 |
|---|---|
| `--sheet` | 시트 이름 (기본: properties) |
| `--key-column` | key 열 이름 (기본: 첫 번째 열) |
| `--glossary` | 용어집 JSON 파일 |
| `--output` | 마크다운 리포트 출력 |
| `--json` | JSON 결과 출력 |

### 도구가 잡지 못하는 항목 (수동 검토 필요)

- 문맥상 어색한 표현 (`미션하고` 등)
- 같은 단어 반복으로 인한 어색함
- 의미 모호함 (`실물 결제` 등)
- 일본어/중국어/태국어의 자연스러움
- 의역의 적정성 (진짜 오역 vs 정상 의역)
