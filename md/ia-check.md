## 0. 목적

unifi.me에 새로 추가·변경·삭제된 메뉴/기능/화면이 있는지 정기적으로 확인해 **`md/IA.md`를 최신으로 유지**하고, 결과를 **주간 리포트**로 남긴다. 리포트는 팀원이 드랍웹에서 열람하므로 **가이드 사이트 zip에도 매 회차 반영**한다.

`md/IA.md`는 Screen ID 네이밍(`주기능_부기능_세부기능_01`, 전부 소문자)의 **어휘 정본**이다.

**주기**: 매주 월요일 10:00 (스케줄 등록됨). 회차 번호 `#N`은 직전 리포트 +1.

**토큰**: Figma·Confluence 조회가 아니므로 **토큰 불필요**(CLAUDE.md 토큰 우선 규칙의 사전 탐색 금지 대상이 아니다).

### 5단계 — `md/IA.md` 갱신

변경 발견 시 해당 트리/표를 갱신하고 **「분석 이력」 표에 오늘 날짜 행을 추가**한다. ⚠️ 추정 → ✅ 실측 승격도 반영한다. **변경이 없으면 `md/IA.md`는 건드리지 않는다.**

### 6단계 — 주간 리포트 발행 (필수 — 변경 유무와 무관)

`reports/ia/ia_check_report_YYYY-MM-DD.md`를 생성한다. 구성은 직전 리포트 형식을 따른다:

헤더 표(점검 대상·방법·간격·결과·**안전 제약 준수**) / 점검 범위(방문 라우트 전량) / 최대 변경 / 🆕 그 밖의 신설·변경 / ⛔ 사용자 승인 대기(Screen ID 어휘) / 변경 없음 확인 / ⬜ 미점검·다음 회차 이월(+ 이번 회차 해소 항목) / `md/IA.md` 갱신 위치 요약.

### 7단계 — 가이드 사이트 버전 발행 (필수 — 리포트를 발행했으면 항상 수행)

팀원이 드랍웹에서 보는 가이드 사이트에 이번 회차 리포트를 싣고 **버전을 +1 올려 새 zip을 만든다**. 상세는 아래 §2.

### 8단계 — 커밋·푸시

```bash
git add md/IA.md reports/ia/ guide/ && git commit   # 메시지: docs(IA): 주간 정기 점검 #N YYYY-MM-DD — <요약>
git push origin main
```

- 변경이 없어도 **리포트는 커밋한다**. 커밋 메시지에 `Co-Authored-By: Claude` 트레일러를 넣는다.
- **⛔ `guide/`를 반드시 함께 커밋한다** — 가이드를 새 버전으로 발행했으면 그 소스가 `guide/`에 남아야 한다. zip만 만들고 `guide/`를 커밋하지 않으면 **다음 세션이 `guide/`를 베이스로 삼는 순간 이번 회차 변경이 사라진다**(#6에서 실제로 이 불일치가 났다).
- **`dropweb/`은 `.gitignore` 대상이므로 zip을 `git add`하지 않는다**(`-f` 강제 추가 금지). zip은 게시 산출물이고 사용자에게 파일로 전달하는 것이 배포 경로다. 커밋 메시지 본문에 "가이드 v{N+1} 발행(zip 미추적)"만 남긴다.
- **push가 remote rejected면** `git fetch origin && git rebase origin/main` 후 재시도(다른 세션과 동시 커밋 가능).
- **게시 확인 후 태그**: 사용자가 드랍웹 업로드를 알려주면 `git tag -a guide-v{N+1}` + `git push origin guide-v{N+1}`. **태그가 라이브 정본 표식**이므로 **게시 전에는 달지 않는다.**

### 9단계 — 결과 보고

점검 범위 · 변경 목록(또는 변경 없음) · 승인 대기 항목 · 리포트 경로·커밋 해시 · **새 가이드 zip 경로·버전**을 요약 보고하고 zip과 리포트를 사용자에게 전달한다(SendUserFile).

**드랍웹 업로드는 사용자가 직접** 한다 — 이 절차는 zip 생성까지만 하고 외부 업로드는 하지 않는다.

## 2. 가이드 사이트 갱신 절차 (7단계의 상세)

**소스 정본은 git 추적 `guide/` 폴더다** — `CLAUDE.md`·`md/landpress.md` §5-1과 같은 기준이다. `dropweb/web3_planning_v{N}.zip`은 **`guide/`로부터 만든 게시 산출물**이며 **zip을 직접 편집하지 않는다.**

### 2-0. ⛔ 베이스 확정 (차단 단계 — `md/landpress.md` §5-1 0단계 그대로 수행)

**`git pull` 후 `guide/`를 베이스로 삼는다.** 그리고 아래를 대조해 `guide/`가 실제로 최신인지 확인한다 — **파일명의 숫자도, mtime도 단독으로 믿지 않는다.**

- ⓐ `guide/index.html`의 **푸터 내부 버전 표기** ↔ ⓑ **최신 `guide-v*` 태그**(`git tag -l 'guide-*' --sort=-v:refname | head -1` — **태그가 라이브 정본 표식**) ↔ ⓒ `dropweb/*.zip` 각 파일의 내부 버전 표기·용어집 임베드 버전·mtime
- **태그나 zip이 `guide/`보다 높으면 `guide/`가 낡은 것이다** — 임의로 진행하지 말고 **불일치를 사용자에게 보고**한 뒤 어느 쪽을 베이스로 할지 확인받는다.
  - 사고 이력: 2026-07-30 구버전 zip을 최신으로 오판해 v5·v6 변경이 빠진 zip을 만들었다 · 2026-09-07 `guide/`를 건너뛰어 소스가 v33에 머무는 불일치를 만들었다.
- IA 리포트 탭의 최신 회차(`#N · YYYY-MM-DD`)도 함께 확인해 **이번 회차 번호**를 정한다. **새 버전 번호는 확정된 베이스의 내부 버전 + 1**이다(파일명 최댓값 + 1이 아니다).
- 작업은 `guide/`에서 직접 하거나, 스크래치패드에 복사해 편집한 뒤 `guide/`에 되돌린다 — 구성은 `index.html` · `style.css` · `script.js` · `img/`(5개 png).

### 2-1. ⛔ 「전체 IA 구조」 표 동기화 (`md/IA.md`를 고쳤으면 필수)

IA 점검 리포트 탭 최상단 `<div id="ia-structure">`의 표는 **팀원이 IA를 확인하는 창구**이고, 데이터는 `index.html` 안 **`IA_DATA` 배열** 한 곳에 있다. `md/IA.md`의 §2 화면 트리·§0 제공 매트릭스가 바뀌었으면 **같은 작업에서 이 배열을 맞춘다** — 두 곳이 어긋나면 팀원이 보는 IA가 틀린다.

- 행 형식: `[뎁스(1~3), 화면명, 라우트/부가표기, Web, LIFF, Wallet, mini]` · 제공도 `1`=제공 `2`=조건부·축소 `0`=미제공
- 표·환경 필터·미제공 숨기기·1뎁스 접기는 배열에서 자동 렌더된다 — **마크업·스크립트는 손대지 않고 배열만 고친다**
- 뎁스 1은 GNB 탭 또는 독립 영역(Apps·결제·로그인), 2는 주요 화면, 3은 하위·팝업·조건 설명

### 2-2. IA 점검 리포트 탭에 이번 회차 추가

`index.html`의 `<div id="tab-iareport">` 안, 기존 `<!-- ═══ YYYY-MM-DD (#N) ═══ -->` 패널 **바로 위**(= 최신순 맨 앞, 단 `#ia-structure` 패널 **아래**)에 새 패널을 넣는다. **기존 패널의 마크업을 그대로 복제해 내용만 교체** — 구성 요소를 임의로 바꾸지 않는다:

- 배지 `<span class="badge badge-indigo">#N · YYYY-MM-DD</span>` + 한 줄 제목(그 회차 핵심)
- 요약 표(점검 대상 / 결과: `md/IA.md` 갱신 여부·승인 대기 건수·이월 해소 건수)
- 🔴 최대 변경은 rose 박스(`rounded-xl bg-rose-50 border border-rose-200`)
- `⚠️ 추정 → ✅ 실측 승격` 표(화면 / 라우트 / 핵심 확인) — 없으면 이 표는 생략
- `<details>` 신설·변경 사항 전체 보기
- 승인 대기가 있으면 amber 박스(`rounded-xl bg-amber-50 border border-amber-200`)
- `<details>` 변경 없음 확인 · 다음 회차 이월 항목
- **변경이 전혀 없던 회차**도 패널은 만든다 — 제목을 "변경 없음 — 점검 범위 N개 라우트"로 하고 요약 표·이월 항목만 채운다.

### 2-3. 버전 표기 3곳 교체

문자열로 찾아 `v{N}` → `v{N+1}`, 날짜는 점검일:

1. `<title>… 기획자 워크플로우 가이드 v{N}</title>`
2. 히어로 배지: `기획자를 위한 사용 가이드 · 개발 지식 불필요 · <b>v{N} (YYYY-MM-DD)</b>`
3. 푸터: `기획자 가이드 <b>v{N}</b> (YYYY-MM-DD)`

### 2-4. 업데이트 이력 탭에 행 추가

`<div id="tab-updates">`의 「버전 요약」 표 맨 위에 `<tr><th><b>v{N+1} · YYYY-MM-DD</b></th><td><b>IA 주간 점검 #N — <변경 요약></b></td></tr>`를 넣고, **직전 버전 행의 `<b>` 강조는 제거**해 최신 행만 굵게 남긴다.

### 2-5. 재압축

**`guide/`의 확정본으로부터** 압축한다. 사이트 루트 파일이 zip 최상위에 와야 한다(하위 폴더로 감싸지 않는다 — `md/dropweb-guide.md` 규격).

```bash
cd guide && zip -r -X ../dropweb/web3_planning_v{N+1}.zip index.html style.css script.js img -x '.*' -x '__MACOSX/*'
```

**기존 버전 zip은 삭제하지 않는다**(버전 이력 보존).

### 2-6. 검증 (네 항목 — 전부 확인하기 전에는 완료로 보고하지 않는다)

1. `unzip -l`로 **최상위에 `index.html`**이 있는지
2. **파일 9개**(html/css/js + img 폴더 + png 5개)가 그대로인지
3. 새 zip **용량이 직전 버전과 비슷**한지
4. **브라우저에서 「전체 IA 구조」 표의 렌더·환경 필터·미제공 숨기기·1뎁스 접기가 실제로 동작**하는지

## 3. 제약

- **서비스 화면에서 어떤 트랜잭션도 실행하지 않는다** — 송금·교환·출석하기·뽑기·위임(Delegate)·QR 결제 시작·상품 구매 등 상태 변경 액션 일절 금지. **조회·탐색만.** 카메라·마이크 권한도 허용하지 않는다.
- **Screen ID를 새로 부여하지 않는다** — 어휘 정정/신설은 **제안으로만** 기록하고 사용자 검토 게이트(`md/IA.md` §3)를 따른다.
- **수정·생성 파일은 넷으로 한정한다**: `md/IA.md` · `reports/ia/*.md` · **`guide/`**(가이드 소스 정본) · `dropweb/web3_planning_v{N+1}.zip`. 작업 트리에 **다른 세션의 미커밋 변경이 있어도 `git add`에 포함하지 않는다**.
- 가이드 사이트는 **기존 버전 zip을 덮어쓰지 않고 새 버전을 추가**한다. 리포트도 날짜별로 누적한다 — **주간 이력 자체가 IA 변경 추적의 근거**다.
- **드랍웹 업로드·공유는 사용자 몫**이다. 외부 서비스에 파일을 올리거나 링크를 발행하지 않는다.
- **Beta 디버그 패널은 쓰지 않는다** (2026-08-10 사용자 결정 · 재론하지 않음) — 좌측 톱니의 「국가 모킹」·「알림 테스트」·「결제 가맹점 진입」은 개발자 도구다. 국가 모킹으로 JP IP·Wallet Mode를 실측 승격하는 방안도 폐기했다. 해당 축은 **실제 접속 환경(VPN·해외 IP·실기기 캡처)으로만** 승격한다.
