# 다국어 번역 검증 방법론 (AI 의미 검증 방식)

> Unifi / GuideKim 등 다국어 리소스 파일(XLSX)을 **ko_KR 기준**으로 검증할 때 사용하는 표준 프로세스입니다.
> 이 문서는 사람 또는 LLM이 의미 단위로 번역 품질을 판정하는 **의미 기반 검증(semantic validation)** 방식을 다룹니다.
> 정규식·문자셋 기반 자동 검증(`validate_translation.py`)과는 상호 보완 관계이며, 두 방식을 함께 쓰면 가장 효과적입니다.

---

## 1. 기본 원칙

1. **ko_KR이 기준(Source of Truth)이다.** 모든 번역은 한국어 원문과 대조하여 판정한다. 영어를 기준으로 삼지 않는다.
2. **원문도 검증 대상이다.** 한국어 원문 자체의 오타·띄어쓰기·외래어 오염을 먼저 점검한다. 원문 오류는 모든 언어로 전이되므로 최우선이다.
3. **3단계 판정을 사용한다.** 모든 항목을 `정확(ok) / 주의(warn) / 오류(err)` 중 하나로 분류한다.
4. **의역은 오류가 아니다.** 의미가 보존된 자연스러운 의역은 `정확`으로 판정한다. 직역체가 오히려 `주의` 대상이 될 수 있다.
5. **일관성을 본다.** 같은 용어가 파일 전체에서 동일하게 번역되었는지 교차 확인한다. 한 항목만 보면 놓치는 문제가 많다.

---

## 2. 판정 기준 (3단계)

| 판정 | 의미 | 적용 사례 |
|------|------|-----------|
| ✓ **정확 (ok)** | 의미·뉘앙스·용어가 모두 올바름. 자연스러운 의역 포함 | 원문 의미를 정확히 전달하고 해당 언어에서 자연스러움 |
| ⚠ **주의 (warn)** | 의미는 통하나 개선 여지가 있음. 경미한 문제 | 용어 표기 불일치, 어순/공백 문제, 뉘앙스 약화, 마침표 누락, 단수/복수 오류 |
| ✗ **오류 (err)** | 의미가 왜곡되었거나 명백한 결함 | 오역, 용어 혼재, 미번역(타 언어 혼입), 차별·혐오 표현, 문자 깨짐/오타 혼입 |

### 판정 시 핵심 질문

각 셀에 대해 다음을 자문한다:

- 원문의 **의미**가 그대로 전달되는가? (의미 왜곡 → 오류)
- 해당 언어 화자에게 **자연스러운가**? (어색 → 주의)
- 같은 용어가 **다른 항목과 동일하게** 번역되었는가? (불일치 → 주의~오류)
- 번역어 안에 **다른 언어 문자**가 섞여 있는가? (혼입 → 오류)
- 부정적·차별적 뉘앙스를 가진 단어를 썼는가? (예: 일본어 `差別的` → 오류)

## 3. 검증 절차

### 0단계: 파일 구조 파악 (선행 필수)

```python
import pandas as pd
xl = pd.ExcelFile(path)
print('Sheets:', xl.sheet_names)
df = pd.read_excel(xl, sheet_name='properties')
print('Columns:', df.columns.tolist())
print('Rows:', len(df))
# 언어별 채움 비율 확인
for col in df.columns:
    print(f"{col}: {df[col].notna().sum()}/{len(df)}")
```

확인 항목: 시트 이름(보통 `properties`), key 열(보통 첫 열 또는 `Key ID`), 전체 행 수, 번역이 채워진 언어 컬럼(비어있는 언어는 검증 대상에서 제외).

### 1단계: 한국어 원문(ko_KR) 점검

번역을 보기 **전에** 원문부터 검증한다. 원문 오류는 모든 언어에 영향을 미친다.

| 점검 항목 | 예시 |
|-----------|------|
| 오타 | `미선` → `미션` |
| 맞춤법 | `지급되요` → `지급돼요`, `소진됬` → `소진됐` |
| 띄어쓰기 | `누리고다양한` → `누리고 다양한`, `필수미션` → `필수 미션` |
| 외래어 오염 | `포이가츠`(일본어 ポイ活 음차) → `포인트 미션` |
| 비표준 공백 | 셀 끝/key 앞 `\xa0`(non-breaking space) |
| 모호 표현 | `피부결과 윤곽` (피부결과? 피부 결?) |

> **실사례:** `포이가츠`는 일본어 「ポイ活」를 한글로 음차한 것으로, 한국어로는 의미가 통하지 않음. 단, 일본어 번역은 원래 표현 「ポイ活」를 정확히 복원함. 이런 경우 **원문 수정**이 정답이며 번역은 정상으로 판정.

### 2단계: 언어별 의미 검증 (ko_KR 대조)

각 언어 컬럼을 ko_KR과 1:1 대조하여 3단계 판정한다. 언어별 중점 점검 사항은 4절 참조.

### 3단계: 용어 일관성 교차 검증

파일 전체를 훑어 **동일 개념이 동일하게 번역**되었는지 확인한다. 이것이 단일 항목 검증보다 중요한 경우가 많다.

```python
# 예: 'Lucky Ball' 관련 태국어 표기가 몇 가지인지 집계
import re
th_terms = {}
for i, row in df.iterrows():
    th = str(row['th_TH'])
    for variant in ['ลัคกี้บอล', 'ลักกี้บอล', 'ลูกโชคดี', 'Lucky Ball']:
        if variant in th:
            th_terms.setdefault(variant, []).append(row[df.columns[0]])
for k, v in th_terms.items():
    print(f"{k}: {len(v)}건 — {v}")
```

## 4. 언어별 중점 점검 사항

검증 과정에서 반복 발견된 언어별 특이 패턴이다.

> ⛔ **패턴 사전의 정본은 `md/check.md` '🔥 실전 패턴 모음'이다** — 새로 발견한 패턴은 **check.md에만 추가**하고 이 문서에는 추가하지 않는다(이원화 방지, 2026-07-27 일원화). 아래는 의미 판정 시의 관점(무엇을 보는가)이며, 구체 사례 축적은 check.md를 참조한다.

### 한국어 (ko_KR) — 원문
- 외래어 음차 오염 (일본어 `ポイ活` → `포이가츠`)
- 줄바꿈 의도로 인한 띄어쓰기 누락 (`누리고다양한`) — 영어 등에 그대로 전이될 수 있음
- 맞춤법: `되요/돼요`, `됬/됐`, 의존명사 띄어쓰기

### 영어 (en_US)
- **원문 오류 전이**: 한국어 띄어쓰기 누락이 `perksand`처럼 붙어버림
- **브랜드 대소문자 일관성**: `K-Beauty` vs `K-beauty`, `Lucky Balls` vs `lucky balls`
- **단수/복수**: `quantity` vs `quantities`, `reward` vs `rewards`
- **관사 누락**: `a temporary network error`
- **용어 선택**: `Distribution`(배포) vs `Payment`(지급) — '지급'에는 Payment가 적합
- **어조**: 공식 UI 문구에 과한 구어체(`You couldn't`) 지양 → `Failed to` / `Unable to`

### 일본어 (ja_JP)
- **`差別的` 절대 금지**: '차별적(discriminatory)'의 부정적 뉘앙스. '차등 지급'은 `差等支給` 또는 `段階的に支給`로
- **자동사/타동사**: `自動消滅されます`(X, 수동태 오용) → `自動消滅します`(O)
- **한국어 문자 혼입**: `500 USDT以상`처럼 한자 `上`이 한글 `상`으로 입력되는 IME 오타
- **조사 누락**: `〜関連案内事項` → `〜に関するご案内` 등
- **미용 용어**: `毛穴の縮小`(정확) vs `毛穴の引き締め`(탄력, 미묘하게 다름)

### 중국어 번체 (zh_TW)
- **`差額` vs `差別`**: '차등(차별화)'을 `差額`(차액)으로 쓰면 오역. `差別發放` / `差異化` 사용
- **`存款` vs `入金`**: 단순 입금 행위는 `入金`, `存款`은 예금/저축
- **`消失` vs `失效`**: 리워드/포인트 만료는 `失效` / `作廢`가 적합
- **숫자·단위 공백**: `100 USDT 以上：幸運球最多 5 個` → 불필요한 공백 제거 `100 USDT以上：幸運球最多5個`
- **어순 일관성**: `最多9個幸運球` vs `幸運球最多9個` — 파일 내 통일
- **표기 혼합**: 카테고리명 `K-購物` vs `K-Beauty`(영문 유지) — 통일 정책 필요

### 태국어 (th_TH)
- **용어 혼재 (최빈 오류)**: 'Lucky Ball'이 `ลัคกี้บอล`(정확) / `ลักกี้บอล`(철자 오류) / `ลูกโชคดี`(직역) / `Lucky Ball`(영어 미번역)로 혼재 → `ลัคกี้บอล`로 통일
- **영어 미번역 혼입**: 태국어 문장에 `Lucky Ball` 영어가 그대로 남음
- **차등 개념 누락**: `차등 지급`의 '차등(ตามระดับ / แบบขั้นบันได)'이 생략되어 단순 '지급'으로만 번역
- **소유격 누락**: `내 예약` → `ของฉัน` 누락

## 5. 심각도·우선순위 분류

수정 권고 시 다음 우선순위를 적용한다.

| 우선순위 | 대상 | 설명 |
|----------|------|------|
| **P0 / P1** | 원문(ko_KR) 오류 | 모든 언어에 전이되므로 최우선. 외래어 오염, 띄어쓰기, 오타 |
| **P1** | 의미 왜곡 오역 | `差別的`, `差額`, `ลูกโชคดี` 등 의미가 틀린 경우 |
| **P2** | 용어 혼재·일관성 | 동일 개념의 표기 불일치. 파일 전체 일괄 통일 |
| **P3** | 표기·형식 | 공백, 어순, 대소문자, 마침표, 단수/복수 |
| **P4 (선택)** | 미세 뉘앙스 | 미용 용어 등 통용되나 더 정밀한 표현 가능 |

> **정책 결정 사항은 자동 수정에서 제외**: 종결 어미 톤(해요체/합쇼체), 마침표 정책, 용어 치환(`공식 계정` vs `공식 채널`)처럼 정책 판단이 필요한 항목은 임의 수정하지 않고 별도 협의.

## 6. 엑셀 수정 적용 방법

수정 시 `openpyxl`로 셀 단위 정밀 변경하고, **변경 전 값을 검증**하여 오작동을 방지한다.

```python
import shutil
from openpyxl import load_workbook
from openpyxl.styles import PatternFill

# 1. 원본 보존 (사본에서 작업)
shutil.copy(src_path, out_path)
wb = load_workbook(out_path)
ws = wb['properties']

# 2. 헤더→열번호, Key→행번호 매핑
headers = {ws.cell(1, c).value: c for c in range(1, ws.max_column+1)}
key_rows = {ws.cell(r, 1).value: r for r in range(2, ws.max_row+1)}

# 3. 수정 적용 + 노란색 하이라이트 + 변경 로그
highlight = PatternFill("solid", fgColor="FFF2CC")
corrections = [
    # (key, lang, new_value)
    ("ms_popup_luckyball_tooltip_desc6", "th_TH", "1,000 USDT ขึ้นไป: ลัคกี้บอลสูงสุด 9 ลูก"),
]
for key, lang, val in corrections:
    r, c = key_rows[key], headers[lang]
    cell = ws.cell(row=r, column=c)
    print(f"[{key}/{lang}] 전: {cell.value} → 후: {val}")  # 변경 전후 로그
    cell.value = val
    cell.fill = highlight  # 변경 셀 시각 표시

wb.save(out_path)
```

원칙:
- 원본은 절대 덮어쓰지 않고 **사본**에서 작업
- 열은 **이름**으로 찾기 (위치는 파일마다 다를 수 있음)
- 변경 셀은 **하이라이트**로 표시
- 변경 전후 값을 **로그**로 남김
- 사용 안 하는 언어 열·서식·열 순서는 **그대로 보존**

## 7. 산출물 표준

검증 작업 시 목적에 따라 다음을 생성한다.

| 산출물 | 형식 | 용도 |
|--------|------|------|
| 검증 결과 대시보드 | 인터랙티브 위젯 / 표 | 언어별 정확·주의·오류 집계 및 항목별 판정 즉시 확인 |
| 상세 리포트 | `*_report.docx` | 총괄 요약 → 공통 이슈 → 언어별 상세 → 우선순위 권고 |
| 수정본 | `*_corrected.xlsx` 또는 `*_updated.xlsx` | 변경 셀 하이라이트 적용된 엑셀 |
| (버전 비교 시) 변경 현황 | 리포트 내 섹션 | 이전 파일 대비 수정/미수정/악화 항목 추적 |

### 리포트 표준 구성

1. **총괄 요약** — 언어별 `✓/⚠/✗` 집계 테이블
2. **공통 이슈** — 용어 혼재 현황, 원문 측 문제 등 횡단 이슈
3. **언어별 상세** — 각 언어 항목별 판정 + 상세 사유 (오류·주의 행 색상 구분)
4. **수정 권고** — P1~P5 우선순위별 조치 사항
