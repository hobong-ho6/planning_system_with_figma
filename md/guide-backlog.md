# 기획자 가이드 업데이트 대기 목록

> **기획자 가이드(`guide/` → `dropweb/web3_planning_v*.zip`)는 건건이 갱신하지 않고 모아서 한 번에 반영한다**(2026-09-15 사용자 결정).
> 푸시할 때마다 「가이드를 업데이트할까요?」를 묻지 않는다 — **이 파일에 등재만 하고 넘어간다.**
> 사용자가 **「가이드 업데이트」를 요청한 시점**에 대기 전건을 제시하고 한 번에 반영한다.

## 왜 모아서 하는가

가이드는 갱신할 때마다 ⓐ 본문 전용 섹션 ⓑ 문서 지도 3곳 ⓒ 업데이트 이력 ⓓ 작업 모드 카드 ⓔ 요청 예시 + 네비 2곳 — **5곳을 모두** 손봐야 하고(`md/landpress.md` §5-1), zip 재생성·헤더 렌더 확인·게시·태그까지 따라붙는다. 변경 1건마다 이걸 돌리면 비용이 과하고 버전만 잘게 올라간다.

## 운영 절차

| 단계 | 하는 일 | 정본 |
|---|---|---|
| **① 등재** | md/ 규칙·스크립트·기능이 바뀌어 가이드와 어긋나면 **이 파일 표에 한 줄 추가**한다. 사용자에게 갱신 여부를 **묻지 않는다** | 이 파일 |
| **①-2 제안** | 대기가 **10건 이상**이거나 **⛔ 차단 규칙 2건 이상**이거나 **마지막 `guide-v*` 태그로부터 2주 경과**면, 푸시 보고 끝에 **한 줄로** 「가이드 업데이트를 할까요?」 제안한다(차단 질문 아님). ⛔ **보류하면 5건 더 쌓일 때까지 재제안 금지** — 제안 시점을 아래 「제안 이력」에 남긴다 | CLAUDE.md 📣 규칙 2-1 |
| **② 리뷰** | 사용자가 「가이드 업데이트」를 요청하면 **대기 전건을 표로 제시**하고 반영 범위를 확정받는다 | 이 파일 |
| **③ 반영** | 베이스 확정(태그가 정본) → 5곳 갱신 → zip 생성 → **headless Chrome 헤더 렌더 확인** | `md/landpress.md` §5-1 |
| **④ 게시** | zip을 사용자에게 전달하고 **게시는 사용자가 수행** → 확인 후 `git tag guide-vN` | `md/dropweb-guide.md` |
| **⑤ 사후** | 이 파일에서 반영분 삭제 · 반영 태그를 비고에 남긴다 | 이 파일 |

> ⛔ **용어집은 예외가 아니라 같은 흐름이다.** 용어집 보완도 `md/glossary-backlog.md`로 모아서 반영하므로(2026-09-14 결정), **용어집 버전이 오르는 그 작업에서 가이드 zip을 함께 갱신**하면 된다(`md/landpress.md` §5-1 「필수 동반」은 그대로 유효). 용어집 반영이 없는 평상시 푸시에서는 가이드를 건드리지 않는다.

> ⛔ **베이스는 `guide-v*` 태그가 정본이다.** 로컬 `guide/index.html`의 버전 표기가 태그보다 낮으면 낡은 베이스다 — 반영 전 `git tag -l 'guide-*' --sort=-v:refname | head -1`로 확인한다(`md/landpress.md` §5-1 0단계).
