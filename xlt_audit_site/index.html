요약

가장 시급한 3건 — 키 이름 손상

키 이름 자체에 보이지 않는 문자가 섞여 있어 FE가 정상 키명으로는 값을 가져올 수 없습니다. 번역 품질 문제가 아니라 동작 문제입니다. 문구 검증으로는 원리적으로 발견되지 않는 부류이며, 이번에 키 이름 전수 점검을 따로 돌려 나왔습니다.

서비스별 현황

서비스마다 키스페이스가 다릅니다. 같은 키가 서비스마다 다른 값으로 등록돼 있어 대조 전 타겟 확정이 전제 조건입니다(md/xlt-verify.md §0).

확정 위반 — 즉시 조치

이견 없이 잘못된 값입니다.

1-A. 키 이름 손상 3건 최우선

2·3은 값까지 깨져 있습니다 — 정상 키가 별도로 존재하고, 두 파손 키는 ko_KR ↔ en_US가 서로 뒤바뀌어 있습니다.

키ko_KRen_US
payment_history_paymentstatus_title 정상결제 상태Payment Status
payment_history_\x08paymentstatus_titlePayment Status결제 상태
payment_history_?paymentstatus_titlePayment Status결제 상태

권고 — 2·3은 정상 키가 있으므로 삭제 대상, 1은 nbsp를 제거해 재등록(값은 그대로). ⚠️ 삭제 전 FE 참조 여부 확인 필수(md/translate.md 키 거버넌스 — 키는 FE 전달 후 임의 삭제 금지).

1-B. 컬럼 어긋남 1건

Dapp Portal · Minidapp_connect_signing_title — zh_TW 칸에 태국어가 그대로 복사돼 중국어 번역이 아예 없습니다.

ko_KR지금 Unifi 시작하고 \n매일 이자 받으세요
th_THริ่มต้นกับ Unifi วันนี้\nและรับดอกเบี้ยได้ทุกวัน
zh_TWริ่มต้นกับ Unifi วันนี้\nและรับดอกเบี้ยได้ทุกวัน ← 태국어

덤으로 th_TH 자체도 오타입니다 — เริ่มต้น(시작하다)의 첫 글자 เ가 빠진 ริ่มต้น. 두 언어를 함께 고쳐야 합니다.

1-C. 문자 오염 64건

① 비표준 공백 nbsp(U+00A0) 63키 — 일반 공백과 눈으로 구분되지 않아 줄바꿈·검색·비교가 깨집니다. 전건 실제 위반입니다.

② 한국어 조사가 중국어에 박힘 1건 — Dapp Portal · unifi_promotion_jpyc_caution_contents9 → zh_TW 本活動於準備의獎勵發放完畢時…

1-D. 빈 값 1건

Unifi · app_detail_receive_done — en_US가 빈 문자열

구 표기 자동 치환 제안

용어집 deprecated_terms의 pattern → recommend로 치환문이 생성돼 있습니다. HANDOFF의 「구 표기 17키」는 Dapp Portal 일부만 본 것이었고 Unifi 10건이 누락돼 있었습니다.

⚠️ 기계 치환을 그대로 쓰면 안 됩니다

단순 문자열 치환이라 문맥에서 어색해집니다. 保持關注(관심을 유지하다) 자리에 명사구 加入好友(친구 추가)가 들어가 문법이 깨집니다.

before…須保持關注至最終獎勵發放日，若中途解除，不論後續是否重新關注…
after…須保持加入好友至…是否重新加入好友…

zh_TW 8건은 원어민 검토 후 after를 손으로 고쳐야 합니다.

언어 컬럼 교차 오염 — 탐지 범위와 사각지대

자동 검증기의 언어 혼입 검사는 문자체계(script) 기반입니다. 20개 교차 조합을 하나씩 주입해 실측한 결과 15개만 탐지합니다.

  • 자동 P0 탐지
  • 부분 탐지(P1) — 칸 전체가 한글 없는 라틴일 때만
  • 미탐지

행 = 오염된 컬럼 / 열 = 그 칸에 잘못 들어간 언어. th → zh_TW는 탐지되며(1-B가 그 사례), 한글·가나·태국 문자가 낀 조합은 모두 잡습니다.

사각지대 ①의 실제 사례 — 신규 발견

Unifi · UF_promotion3_detail_caution_desc3 — ja_JP 칸에 번체 중국어. 자동 검사를 통과한 P0입니다.

ko_KR리워드는 KAIA로 일괄 지급
ja_JP獎勵將以 KAIA 統一發放 ← 중국어. 일본어라면 「リワードはKAIAで一括支給」
en_USRewards paid in KAIA
th_THจ่ายรางวัลเป็น KAIA ทั้งหมด

獎勵·發放은 번체 중국어 어휘로 일본어에서는 쓰지 않습니다. 형제 키 UF_promotion3_detail_caution_desc1은 ja가 정상 일본어(イベント参加後30日間…支給されます。)라 대비가 분명합니다.

보완 스캔 (A) — ja_JP == zh_TW 동일 셀

CJK 5자 이상만 남깁니다. 約 {{0}}·{{0}}個·通知·進行中처럼 짧은 한자 표기는 일본어와 번체 중국어에서 실제로 같아 정당한 우연 일치입니다(4자 이하 111건 제외).

번역 누락 후보 — 사각지대 ②

일부 언어만 고유 문자가 없는 행입니다. 4개 언어 전부 라틴인 151키는 의도된 미번역 UI 라벨(Contract·Balance·Powered by Kaia Wallet)이므로 제외했습니다.

⚠️ 이 스캔은 방향을 판정하지 않습니다. UF_reward_history_user는 "ko·ja·zh 미번역"으로 걸리지만 실제로는 th가 USDT를 ดอลลาร์สหรัฐฯ로 과잉 번역한 것입니다. 후보 목록이며 건별 판단이 필요합니다.

오탐 판정 — 조치 불필요

자동 등급을 그대로 읽으면 안 되는 이유입니다. 전수 스윕은 캠페인 게이트와 모집단이 달라 오탐 비중이 큽니다.

유형판정 근거
P1 용어 불일치검증기는 ko에 등재 용어가 있으면 다른 언어에도 등재 번역이 문자열로 있어야 한다고 봅니다. 전수 모집단에서는 정상 의역이 대량으로 걸립니다. 등급이 아니라 용어집 매핑이 좁다는 신호입니다
P2 마침표 스타일"문장형 중 소수 스타일"을 찾는 방식이라 모집단이 커지면 의미를 잃습니다. 캠페인 단위에서만 유효합니다
P1 언어 의심ko 칸에 한글 없이 라틴 문자열 — 대부분 브랜드·토큰 심볼(USDT, Unifi)
P0 언어 혼입 · 언어 선택 라벨UF_settings_display_language_ko/ja/th/cn·_currency_thb 5키는 5개 언어 전부 자기 언어 표기(한국어·日本語·ภาษาไทย·中文(繁體)·THB (฿))로 의도된 값입니다. 언어 선택기는 어느 로케일에서든 각 언어를 그 언어로 보여줍니다. 한 키가 여러 칸에서 걸려 이슈 수가 키 수보다 많습니다
P0 언어 혼입 · zh_TW ・구분자 ・(U+30FB)가 검증기의 가나 범위에 걸립니다. 중국어에서 정상 사용 → 검증기 한계

서비스 간 값 분기 — 공통 키의 절반이 다릅니다

Unifi와 Dapp Portal이 서로의 키를 구값 사본으로 보유합니다.

키UnifiDapp Portal

UF_(UIT)의 정본은 Unifi이며 거기서는 {{0}}(279키)로 CLAUDE.md 규칙과 일치합니다. Dapp Portal의 UF_ 사본이 {0}이고, 이것이 세션 #16 「UIT 치환자 불일치」의 원인이었습니다 — 문서 규칙이 아니라 조회 대상이 틀렸습니다.

이 감사 도중 UF_floating_jpyc_banner_title이 Unifi에서 삭제됐습니다(2,131 → 2,130키, 약 1시간 간격 두 조회의 차이). 캐시 금지 규칙이 왜 필요한지의 실증이며, 제안 적용 시 --apply의 무결성 가드(before 대조)가 이 상황을 막습니다.

다음 단계

  1. 키 이름 손상 3건 — FE 참조 여부 확인 후 조치(2·3 삭제, 1 재등록)
  2. zh_TW 구 표기 8건 — 원어민 검토로 after 수정 → --apply로 업로드 엑셀 생성
  3. 용어집 보완 — 확인 다의어 th 매핑 · 구분자 ・ 처리(md/landpress.md 절차, 사용자가 CMS 반영)
  4. 검증기 보완 — ja==zh 동일 셀 검사 + 일부 언어만 라틴 검사를 P1로 추가. P1 기준선이 바뀌므로 A/B 실측 후 채택
  5. 키 이름 검사 상시화 — verify_xlt_glossary.py에 제어문자·비ASCII·앞뒤 공백 검사 편입 여부 결정

재현

python3 scripts/fetch_glossary.py scripts/glossary.json
