# handoff/ — 계층 구조 계약

핸드오프는 **3계층**이다. 계층을 섞으면 4명·8머신 환경에서 충돌하거나 남의 결정을 모르고 재작업한다.

| 계층 | 파일 | 담는 것 | 쓰는 사람 | 상한(바이트) | 줄(보조) |
|---|---|---|---|---|---|
| 공유 정본 | `../HANDOFF.md` | 전역 규칙·스킬 표·전역 컨텍스트 노트·**프로젝트 인덱스** | 규칙 변경 시에만 | **20KB** | 100 (인덱스 제외) |
| 프로젝트 | `projects/{name}.md` | 위키·엑셀·현재 상태·다음 할 일·그 프로젝트의 결정/⛔종결/세션 기록 | 담당자 | **18KB** | 120 |
| 사람 | `people/{person}.md` | hostname별 경로·환경 복구·PC 간 차이·개인 선호 | 본인만 | **3KB** | 40 |
| 레인(락) | `lanes/{...}.md` | **전역 자원 점유** — 파일 존재 = 점유 중 | 전역 자원 만질 때만 | 2KB | 20 |

> ⛔ **상한은 줄이 아니라 바이트로 잰다**(2026-09-13 정정). 불릿 하나가 2,000자여도 1줄이라 줄 수는 비용을 반영하지 못하고, 한글은 **1자 = 3바이트**라 「11,776자」가 실제로는 20KB다.
> ```bash
> wc -c HANDOFF.md handoff/people/*.md handoff/projects/*.md
> ```
> **세션 시작에 실제 주입되는 것은 `HANDOFF.md` + 담당자 `people/` 1개뿐**(프로젝트 본문은 대상이 정해진 뒤에만 읽는다) → **합계 24KB 이내**로 유지한다. 2026-09-13 실측 22.3KB.
> 넘으면 **지우지 말고** 상세를 `md/` 정본으로 옮기고 원 위치에는 **경고 한 줄 + 포인터**만 남긴다(포인터 압축).


## 세션 정리 시 어디에 쓰는가 — diff로 판별한다

```bash
git diff --name-only origin/main...HEAD
```

| 건드린 경로 | 갱신 대상 |
|---|---|
| `guide/` · `dropweb/` · `md/` · `scripts/` · `templates/` · 용어집 | `HANDOFF.md` + **레인 파일 삭제** |
| `xlt/` · `reports/gate/{prefix}_*` · 특정 위키 페이지 | `projects/{prefix}.md` |
| 의존성 · 경로 · VPN · PC 고유 이슈 | `people/{나}.md` |
| 프로젝트 파일을 갱신했으면 | `HANDOFF.md` 인덱스의 **그 1줄만** 동기화 |

세 곳 다 해당하면 세 곳 다 쓴다. 절차 정본은 `.claude/skills/handoff/SKILL.md`.

## 온보딩 (자동 판별)

훅이 `handoff.person` · `user.email` · **이 PC의 hostname이 어느 `people/*.md`에 등록됐는지** · 저장소 커밋 author 이력을 보고 상태를 **A~E**로 판별해 주입한다. Claude는 그 상태의 조치만 수행하고, **판별로 알 수 있는 것은 묻지 않는다**(A는 질문 0개 / C는 1개 / D는 3개). 상태별 절차는 `.claude/skills/handoff/SKILL.md` 「온보딩」.

새 사람이 합류하면 `people/{키}.md`(템플릿 복사) + `HANDOFF.md` 인덱스 담당자만 채우면 되고, 그 PC의 hostname을 PC 표에 적어두면 **다음부터 그 PC는 상태 A로 자동 인식**된다.

## 사람 식별 (필수 설정 — PC 2대 모두 동일하게)

`people/{person}.md` 자동 선택과 커밋 author 식별에 쓴다. hostname은 식별자가 아니다(1인 2PC).

```bash
# ⚠️ 아래 세 줄은 예시 값이다. 그대로 실행하지 말고 본인 값으로 바꿔 실행할 것
# (2026-08-20에 예시 값이 그대로 실행돼 5커밋이 잘못된 author로 푸시된 전례)
git config --global user.name "<내 이름>"
git config --global user.email "<내 메일>"
git config --global handoff.person <사람키>
```

훅 판별 순서(증거 우선): ① `handoff.person`(**확정**) → ② 이 hostname이 등록된 `people/*.md` → ③ `user.email`이 본문에 있는 `people/*.md` → ④ `user.email`의 `@` 앞부분이 파일명과 일치 → ⑤ 없으면 신규(D).
**②~④는 `handoff.person`이 없을 때만 쓰이고, ④의 추정 키가 실제 파일명과 다르면 훅이 그 사실을 경고한다** — 추정 키로 새 사람 파일을 만들면 안 된다.

⚠️ **②③은 `people/*.md` 본문을 스캔한다** — PC 표의 hostname과 헤더 identity의 이메일이 그 근거다. 정리·압축할 때 이 둘을 지우면 **새 PC에서 신원 판별이 조용히 깨진다**(2026-08-20 `hogeun.md`를 40줄로 줄일 때 이메일을 헤더로 옮겨 보존하고 회귀 테스트로 확인했다).

## 분할 금지

**전역** 결정·⛔종결은 프로젝트 파일에 두지 않는다 — 다른 프로젝트 세션이 못 보고 재제안한다. 애매하면 `HANDOFF.md`에 둔다.

## HANDOFF.md에 쓰는 것 / 쓰지 않는 것 · 분량 (2026-09-22 `HANDOFF.md` 머리말 주석에서 이관)

> 매 세션 주입되는 파일이라 주석으로 들고 있을 이유가 없어 계약 정본인 이 파일로 옮겼다.

```
════════════════════════════════════════════════════════════
핸드오프는 3계층이다. 계층 계약·갱신 대상 판별: handoff/README.md
절차 정본(세션 시작·종료): .claude/skills/handoff/SKILL.md

■ 이 파일에 쓰는 것 — 전역만
  · 모든 프로젝트에 적용되는 규칙·도구·결정
  · 프로젝트 인덱스(활성 프로젝트 1줄씩)
■ 이 파일에 쓰지 않는 것
  · 특정 위키·화면·키의 상태 → handoff/projects/{name}.md
  · PC·경로·환경               → handoff/people/{person}.md
  · 지금 점유 중인 전역 자원    → handoff/lanes/{...}.md
■ 분량: 20KB 이내(`wc -c HANDOFF.md` — 줄 수가 아니라 바이트로 잰다. 한글 1자=3바이트).
  이 파일 + 담당자 people/ 1개가 매 세션 주입된다 → 합계 24KB 이내 유지(2026-09-13 실측 22.3KB).
  넘치면 규칙은 md/ 문서로 옮기고 경고+포인터만, 프로젝트 상태는 projects/ 로 내린다.
════════════════════════════════════════════════════════════
```

### ⛔ 재팽창 방지 기준 (2026-09-22 신설)

**`HANDOFF.md`에 남기는 것은 셋뿐이다.** ① 활성 프로젝트 1줄씩 ② **모르면 사고 나는 차단 규칙 한 줄** ③ 어디를 열어야 하는지(포인터).
근거·경위·절차 상세는 전부 `md/`(실측은 `md/handoff-context.md` · 결정은 `md/decisions.md`)나 `handoff/projects/`로 내린다.
「한 줄 상태」는 **말 그대로 한 줄**이다 — 길어지면 그 내용은 프로젝트 파일에 있어야 할 것이다.

## 이 구조가 왜 이런가 — 2026-08-20 구조 결정 6건 (`handoff/projects/system-meta.md`에서 이관 · 2026-09-22)

> 3계층 전환 당시의 결정과 이유다. **재작업·재제안 금지** 대상이며, 구조를 바꾸자는 제안이 나오면 여기를 먼저 본다.

| 날짜 | 결정 | 이유 |
|---|---|---|
| 2026-08-20 | **온보딩 판별은 「확정 키 → 증거 역추적」 우선순위로** — `user.email`에서 딴 키는 **추정**으로 표시하고, 실제 파일명과 다르면 새 사람 파일을 만들지 않는다 | 추정 키가 채워져 있으면 **hostname 증거가 이미 있어도 `C` 분기가 걸리지 않아** `E`로 오판하고 **중복 사람 파일 생성을 지시**했다(이 iMac 실측). 신호를 늘릴 때 우선순위와 「추정」 표시를 같이 넣지 않으면 추정이 확정을 가린다. 커밋 `cf44ac6`~ |
| 2026-08-20 | **핸드오프를 사람이 아니라 3계층으로 분리** — 공유 정본 + 프로젝트 + 사람 + 레인 | 사용자별 분할은 실제 사고를 못 막는다. 세션 #20↔#21 덮어쓰기는 **같은 사람·같은 PC**였고, 사고 원인은 전부 **공유 산출물 동시 쓰기**였다. 사용자별로 나누면 남의 진행을 못 봐 위험이 오히려 커진다. 축은 **작업 대상(프로젝트)** 과 **점유(레인)** 다 |
| 2026-08-20 | **레인은 단일 표가 아니라 파일 단위** — 파일 존재 = 점유 | 8머신이 같은 표 줄을 고치면 그 표가 충돌 핫스팟이 된다. 파일 생성/삭제는 **머지 충돌이 원리적으로 발생하지 않고** 현황 파악이 `ls` 한 줄이다 |
| 2026-08-20 | **인덱스는 활성 프로젝트만** — 종료분은 `projects/_archive/`로 이동 | 인덱스는 매 세션 주입된다. 활성만 유지하면 시간이 지나도 주입량이 무한 증가하지 않는다(유일한 선형 증가축) |
| 2026-08-20 | **hostname은 식별자가 아니다** — 담당자는 git identity(`handoff.person`) | 한 사람이 PC 2대를 쓰고 한 PC를 여러 사람이 쓸 수 있다. hostname은 `people/*.md` 안의 세부 정보로 내려갔다 |
| 2026-08-20 | **`.claude/hooks`를 `.gitignore` 화이트리스트에 추가** | `.claude/*`가 기본 차단이라 훅 스크립트가 커밋되지 않고 **`settings.json`만 전파돼 다른 PC에서 훅이 조용히 깨진다**. 커밋 직전 `git add`가 이를 잡았다 |
